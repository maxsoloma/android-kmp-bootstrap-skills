# Select checks for the affected application

Read the actual project's README, project.yaml, module.yaml and bootstrap.json;
never assume every generated module is present. Preserve wrapper/version pins.
Use existing tests and actual platform commands from that project, verifying new
CLI syntax with current official documentation. Select affected shared logic and
its platform consumers. Record acceptance and command selection in the task packet.

For projects generated by this plugin, the documented wrapper commands include:

| Platform | Build | Execute tests | Additional acceptance |
| --- | --- | --- | --- |
| Android | `./kotlin build --platform android` | `./kotlin test --platform android` | Emulator/device interactions for changed UI/lifecycle |
| iOS simulator | `./kotlin build --platform iosSimulatorArm64` | `./kotlin test --platform iosSimulatorArm64` | Full Xcode, simulator runtime; SwiftUI host checks from project README |
| Desktop | `./kotlin build --platform jvm` | `./kotlin test --platform jvm` | Launch/interact for changed UI |
| Browser Wasm | `./kotlin build --platform wasmJs` | `./kotlin test --platform wasmJs` | Browser flow, CORS/history/storage behavior where affected |

On Windows use the checked-in kotlin.bat. Serialize iOS simulator tests if tools
share one simulator. Do not provision devices/cloud credentials or install/upgrade
a global toolchain just to make a check green without the appropriate authority.

Examples of meaningful behavioral coverage: loading/success/error/cancellation
for a request, restart persistence and storage failure, back navigation and
controller lifetime, platform adapter boundary cases. Choose only relevant cases.
A fake response test does not prove connectivity with a real service. A simulator
build does not prove signing, APNs, device deployment or store readiness.

Every check record carries command, log path, observed exit code and status.
Retain failures and skipped checks; do not flatten them into passed. A required
unavailable check blocks that acceptance task, while unrelated tasks can continue.
Report exact missing SDK, host, simulator, configuration or network requirement.

For simulator setup, inspect the installed runtime's supportedDeviceTypes; a type
listed globally may be incompatible with that runtime. Use the device manager
shipped by the installed Xcode (some hosts use DeviceHub) and check the active
screen/posture on foldable or multi-display simulators before interpreting a
black screenshot. Preserve actual launch, visual and interaction evidence.
